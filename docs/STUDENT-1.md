# სტუდენტი 1 — კატალოგი და ფილტრაცია

## პირადი სამუშაო და საკუთრება

- მოდული და სტილი: `src/components/student1/`.
- მთავარი JSX ფაილი: `src/components/student1/index.jsx`.
- საკუთარი Custom Hook: `src/hooks/student1/useDebounce.js`.
- კომპონენტების იერარქია: `CatalogModule → ProductGrid → ProductCard`.
- ფუნქციები: ძებნა, კატეგორია, ჩატვირთვა, ფილტრების გასუფთავება, კალათაში დამატება და რჩეულების ღილაკი.
- საკუთარი ტესტი: `tests/student1.test.jsx`.

საერთო ინფრასტრუქტურა ოთხივე პაკეტში იდენტურია. `useLocalStorage.js` სტუდენტი 2-ის ავტორობით შექმნილი საერთო დამოკიდებულებაა. საკუთარ Hook-ად სტუდენტი 1 წარადგენს ზემოთ მითითებულ ფაილს.

## გარემოს ინდივიდუალური მომზადების დემონსტრაცია

1. დააყენე Node.js 22.12+ და VS Code.
2. ტერმინალში აჩვენე `node -v` და `npm -v`.
3. ახალი საცდელი სამუშაო საქაღალდიდან შექმენი Vite-ის პროექტი:

```bash
npm create vite@latest student-1 -- --template react
cd student-1
```

4. გენერირებული საწყისი `src`, `public`, `index.html`, `package.json` და კონფიგურაცია ჩაანაცვლე მოწოდებული ინდივიდუალური პაკეტით. ახალი scaffold-ის ზედმეტი `eslint.config.js` და საწყისი დემო-ფაილები არ დატოვო. ეს გააკეთე ახალ სამუშაო საქაღალდეში და არა უცვლელად შესანახ ჩაბარების არქივში.
5. შეინარჩუნე პაკეტის React 18.3.1, Vite და lock ფაილი.
6. VS Code-ში გახსენი შენი პროექტი და გაუშვი:

```bash
npm ci
npm test
npm run build
npm run dev
```

ამ ნაბიჯებს თითოეული სტუდენტი პირადად ასრულებს; არქივი არ შეიცავს მათ სახელზე შექმნილ გამოგონილ ისტორიას.

## ინდივიდუალური მოდულის შემოწმება

შენს პაკეტში ნავიგაციაში მხოლოდ შენი მოდული ჩანს. „პროდუქტის სწრაფი არჩევა“ საერთო კომპონენტია: გახსენი და დაამატე პროდუქტი კალათაში ან რჩეულებში, თუ შენი მოდულის შემოწმებისთვის მონაცემი გჭირდება. მიმოხილვების მოდულში პროდუქტი საკუთარი ჩამოსაშლელი სიით ირჩევა.

## წარდგენისას ასახსნელი საკითხები

1. აჩვენე სამუშაო გარემო, საქაღალდეები და JSX.
2. შენს კოდში აჩვენე `useState`, `useEffect`, `useContext`, `useRef`, `useMemo`, `useCallback` და საკუთარი Hook.
3. ახსენი Hook-ების dependency array-ები და effect-ის cleanup, სადაც გამოიყენება.
4. აჩვენე მშობელი და შვილი კომპონენტები, მონაცემების props და callback props.
5. აჩვენე `children`-ით კომპოზიცია, `.propTypes` და პირობითი რენდერი.
6. გაუშვი ფუნქციები, შენი ტესტი და production build.
7. აჩვენე რეალური GitHub ცვლილებები და საერთო პროექტთან შეერთება.
